# Промптове за демото в Claude Code

## Преди старта (VS Code + Claude Code)

1. Разархивирайте папката, например в `C:\Projects\apteka-demo`.
2. Във VS Code: **File → Open Folder** → изберете `apteka-demo`.
3. Отворете Claude Code (иконата в страничната лента). `CLAUDE.md` се чете автоматично.
4. Пратете **Промпт 0** — Claude сам инсталира .NET, Git и Docker чрез `setup.ps1`.
   Ще пита за разрешение за командите и Windows може да покаже прозорец за администраторски права — потвърдете.
5. След това промптовете по-долу, **един по един**.

---

## Промпт 0 — автоматична инсталация

```
Пусни setup.ps1 в тази папка, за да инсталираш .NET 10 SDK, Git, Docker Desktop,
dotnet-ef и C# Dev Kit за VS Code:
powershell -ExecutionPolicy Bypass -File .\setup.ps1
После провери с dotnet --list-sdks, git --version и docker version.
Ако нещо липсва или Docker не върви, кажи ми точно какво да направя
(например рестарт или отваряне на Docker Desktop). Накрая направи git init
и първи commit с CLAUDE.md, PROMPTS.md и setup.ps1.
```

Ако Claude каже, че трябва рестарт: рестартирайте, отворете Docker Desktop, изчакайте „Engine running“,
отворете пак VS Code и пратете: `Провери отново dotnet, git и docker и продължи.`

## Промпт 1 — план и скелет

```
Прочети CLAUDE.md. Предложи структурата на solution-а и схемата на базата
(ентитети, връзки, индекси, ограничения) за демото. Не пиши код, преди да
одобря плана.
```

След одобрение:

```
Добре, направи го: solution със src/ и tests/ проектите от CLAUDE.md,
docker-compose.yml с PostgreSQL 16, EF Core DbContext и първа миграция,
seed с измислени данни (50 стоки с мерки и баркодове, 3 доставчика,
потребители manager/pharmacist), README.md на български.
Накрая пусни dotnet build и dotnet test и ми кажи резултата.
```

## Промпт 2 — номенклатура

```
Направи екрана „Номенклатура“: списък с търсене по име и баркод,
създаване и редакция на стока с мерки (Factor) и баркодове.
Валидации: точно една мярка с Factor = 1, уникален баркод.
Добави тестове и пусни dotnet test.
```

## Промпт 3 — доставка и партиди

```
Направи екрана „Доставка“: доставчик, фактура, редове
(стока, мярка, количество, партида, срок, покупна и продажна цена).
„Запиши“ = Draft, „Публикувай“ = в една транзакция създава партидите и
StockMovement записите; публикувана доставка не се редактира.
Integration тестове с Testcontainers: публикуване → правилна наличност
в най-малката мярка.
```

## Промпт 4 — наличност

```
Направи екрана „Наличност“: по стока и по партида, количество в кутии и
в най-малка мярка, филтър „изтича до 90 дни“. Наличността се смята
само от StockMovement.
```

## Промпт 5 — каса

```
Направи екрана „Каса“ за свободна продажба, изцяло с клавиатура:
поле за баркод с постоянен фокус, Enter добавя ред, F2 количество,
F9 плащане (в брой / карта), Esc отказ. Изписване по FEFO, изтекли
партиди не се продават, без отрицателна наличност. Паралелен тест:
две продажби на последната кутия едновременно — само едната минава.
```

## Промпт 6 — продажби за деня и сторно

```
Направи екрана „Продажби за деня“ със сторно на продажба.
Сторното създава обратни StockMovement записи и ред в AuditLog;
нищо не се изтрива. Тестове за връщане на наличността.
```

## Промпт 7 — преглед

```
Прегледай целия код спрямо правилата в CLAUDE.md (пари, количества,
транзакции, одит, лични данни). Изброй нарушенията и ги поправи.
Пусни всички тестове и обнови README.md.
```

## Полезни съвети

- Ако нещо не е както искате, кажете го конкретно: „на касата Enter трябва да…“.
- Пазете работата в Git: след всеки успешен промпт — `commit`.
- Нови идеи записвайте в `docs/BACKLOG.md`, не ги добавяйте насред етап.
