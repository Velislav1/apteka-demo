# Контекст на проекта (какво е решено и защо)

Резюме на работата до 2026-11-15, за да може Claude Code на друг компютър да продължи без стария разговор.
Прочети заедно с `CLAUDE.md` (правила и модел) и `docs/NEXT-STEPS.md` (как да продължиш).

## Цел

Нова аптечна програма за българска аптека, заместител на „Аптека Експерт 2“. Сега е демо:
номенклатура, доставки с партиди, наличности и проста каса. Фискален принтер, НЗИС, НЗОК, БОВЛ
и НАП са извън демото (виж `docs/BACKLOG.md`). Интерфейсът е на български, кодът и commit-ите на английски.

## Как работим

- Работата върви на малки стъпки по `PROMPTS.md`. Преди голяма промяна Claude предлага план и чака одобрение.
- Проектът се води в private хранилище `Velislav1/apteka-demo` и се развива на два компютъра.
- Не се добавя функционалност извън демото; идеите отиват в `docs/BACKLOG.md`.

## Какво е направено

1. **Инструменти:** .NET 10 SDK, Git, Docker Desktop (с WSL 2), `dotnet-ef`, C# Dev Kit (чрез `setup.ps1`).
   Docker поиска включване на Virtual Machine Platform и обновяване на WSL; след рестарт `docker version` работи.
2. **Скелет (одобрен план):** модулен монолит с 6 модула (Catalog, Purchasing, Inventory, Sales, Identity, Audit),
   по 4 проекта на модул (`Contracts`, `Domain`, `Application`, `Infrastructure`), `SharedKernel`
   (`Money`, `Quantity`, `Entity`, `Result`), `Infrastructure.Common`, Blazor host, тестове и CI.
   Правилата на архитектурата се проверяват автоматично от `Apteka.ArchitectureTests`.
3. **Проверка:** 36 теста зелени, включително интеграционни с PostgreSQL в Testcontainers.

## Решения, взети по пътя

- Без MediatR (платен): use cases са обикновени handler класове.
- Правилата за зависимости между модулите се проверяват върху `.csproj` файловете, защото празни проекти не оставят
  референции в DLL-а.
- `global.json` избира Microsoft Testing Platform (нужно за xunit v3 на .NET 10). Тестове: `dotnet test --solution Apteka.sln`.
- `appsettings.Development.json` е извън git (правило 8 за пароли); в git е само `.example.json`.
- Windows Smart App Control блокира някои току-що компилирани празни DLL-и; тестовете за типове ги пропускат.

## Решено да се върви модул по модул

Общият план на базата за всички модули наведнъж (Промпт 1) е **пропуснат нарочно**. Схемата се прави за всеки
модул в неговия промпт (2: Catalog; 3 и 4: Purchasing и Inventory; 5 и 6: Sales; 7: преглед).
Към всеки промпт се добавя: „Спазвай модулната структура и правилата в CLAUDE.md.“

## Предложения, още НЕ потвърдени (потвърди ги с Claude в съответния модул)

- Ключове `uuid` (`Guid.CreateVersion7()`); без външни ключове между схеми, само `uuid` към другите модули.
- Наличност = сума от `StockMovement`; преди проверка се заключва редът на партидата (`SELECT … FOR UPDATE`).
  `stock_movements` и `audit_log` са само за добавяне, с тригер срещу `UPDATE`/`DELETE`.
- Общ `IUnitOfWork` (една Npgsql връзка и транзакция за всички модули) и общ EF audit interceptor, когато първата
  функционалност ги поиска.
- Нов ред в `batches` за всеки ред от доставка. Чернова на доставка може да се променя, публикуваната никога.
  `UNIQUE(supplier_id, invoice_no)`.
- Допълнения към модела: `sale_lines.vat_rate`, таблица `sale_reversals`, номер на продажба от PostgreSQL sequence,
  отделен тип `UnitPrice` с 4 знака (цените за най-малка мярка са `numeric(12,4)`, `Money` е 2 знака).
- Seed само в Development, с измислени данни: 50 стоки, 3 доставчика, потребители `manager` и `pharmacist`;
  баркодове EAN-13 с префикс 200–299; пароли само в `appsettings.Development.json`.
